# NeoTeam Social Run · Wallet setup

The QR/check-in flow works without Wallet credentials. Wallet buttons appear only when the corresponding provider is configured.

## Google Wallet

Google Wallet is generated by the Next.js server route as an Event Ticket and uses the same secure `checkin_token` as the on-page QR.

Configure these Vercel server environment variables:

- `GOOGLE_WALLET_ISSUER_ID=3388000000023199339`
- `GOOGLE_WALLET_SERVICE_ACCOUNT_EMAIL`
- `GOOGLE_WALLET_PRIVATE_KEY_BASE64` — base64 of the complete PEM private key
- `GOOGLE_WALLET_CLASS_SUFFIX=neoteam_social_run_2026`
- `GOOGLE_WALLET_ORIGIN=https://<production-domain>`

The service account must be authorized for the Google Wallet issuer. For this project, the validated issuer is `3388000000023199339` (Landak Studio), and the Event Ticket Class is `3388000000023199339.neoteam_social_run_2026`.

Official guide: https://developers.google.com/wallet/tickets/events/web

## Apple Wallet

Apple Wallet passes are signed inside the Supabase Edge Function `apple-wallet-pass`. Do not place Apple certificates in browser-visible variables or commit them to the repository.

Configure these **Supabase Edge Function secrets**:

- `APPLE_PASS_TYPE_ID`
- `APPLE_TEAM_ID`
- `APPLE_WWDR_CERT_BASE64`
- `APPLE_PASS_CERT_BASE64`
- `APPLE_PASS_KEY_BASE64`
- `APPLE_PASS_KEY_PASSPHRASE` (only if the exported key has a passphrase)

You need an Apple Developer membership, a Pass Type ID, its Pass Type ID certificate/private key, and the Apple WWDR certificate chain. The function produces a signed `.pkpass` Event Ticket containing the NeoTeam QR.

Official guide: https://developer.apple.com/documentation/walletpasses/building-a-pass

## QR payload

Participant QR payloads use:

`NEOTEAM-SR26:<random UUID>`

The UUID is stored in `registrations.checkin_token` and is independent from the visible sequential registration code. `/admin/checkin` accepts both the secure QR token and the visible registration code as a manual fallback.
